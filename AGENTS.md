# AGENTS.md

Guidance for AI coding agents working in this repository.
Read `README.md` for the human-facing explanation.
This file covers what you need in order to change things safely.

## What this repo is

An **example** kustomize layout for storing oc-mirror v2 output in Git and rolling the mirrored operator catalogs out to disconnected OpenShift clusters.
There is no application code and no CI.
Everything is kustomize YAML plus Markdown, with a few bash scripts (run through `just`) that generate the version components and overlays, sort mirror sets and format YAML.
The registries (`dc1-quay`, `edge-harbor`), hostnames and catalog choice are made up.
The oc-mirror output under `examples/` is real, except `examples/redhat-operators/cluster-resources/itms-oc-mirror.yaml`, which is hand-written (see `examples/README.md`).

## Layout

```
mirrors/<registry>/kustomization.yaml            lists the registry's catalog dirs; includes components/registries/<registry>; generated
mirrors/<registry>/<catalog>/kustomization.yaml  wrapper: resources [cluster-resources] + components/catalogs/<catalog>; generated
                                                 <catalog> (e.g. redhat-operators) is also the CatalogSource's stable name
mirrors/<registry>/<catalog>/cluster-resources/  oc-mirror output (sorted, formatted) + a generated kustomization.yaml
components/catalogs/<catalog>/                   catalog labels (labels field) + IDMS/ITMS rename (kind-only targets); created if missing
components/rename-catalogsources/<catalog>/      CatalogSource -> stable name (name-anchored target); created if missing; the list is generated
components/registries/<registry>/                registry label; hand-written (build warns if missing)
components/ocp-version/<x.y>/                    selects one OpenShift version (includes deselect-all); generated
components/ocp-version/{deselect-all,prune-deselected}/   see components/ocp-version/README.md
components/common/                               prune-deselected, then rename-catalogsources
base/                                            OperatorHub/cluster (disableAllDefaultSources)
overlays/<x.y>/<registry>/                       resources [base, mirrors/<registry>]; components [ocp-version/<x.y>, common]; generated
examples/<catalog>/                              the real oc-mirror runs: imagesetconfig.yaml + cluster-resources/
justfile                                         recipes: build (default: clean + regen + render), clean, regen, render, sort, catalogs, kustomizations, versions, overlays, fmt, generate, check, hooks
target/<x.y>/<registry>/                         rendered overlays, one <kind>-<name>.yaml per object; git-ignored, emptied by just clean, filled by just render
scripts/*.sh                                     what the recipes run; lib.sh holds shared helpers; fail unless run through just
scripts/templates/                               envsubst templates for the generated files and created components
lefthook.yml                                     pre-commit: sort mirror sets, then generate, then yamlfmt
.yamlfmt.yaml                                    yamlfmt settings; excludes examples/, scripts/templates/ and target/
```

`just build` rebuilds these from scratch, so hand edits there are lost (change `scripts/templates/` or the scripts instead):

- every `kustomization.yaml` under `mirrors/`, with `kustomize create --autodetect --recursive` plus yq for the components
- `components/ocp-version/<x.y>/` and `overlays/`, from the versions and registries found in `mirrors/`
- the list in `components/rename-catalogsources/kustomization.yaml`

`components/catalogs/<catalog>/` and `components/rename-catalogsources/<catalog>/` are only created when missing, from the index name in the catalog's own `cc-*.yaml` file names.
After that they're hand-maintained and never regenerated.

## Rules that must not be broken

1. **Never hand-edit files under `cluster-resources/`**, in `mirrors/` or `examples/`.
   They are oc-mirror output.
   `examples/` is kept byte-for-byte.
   In `mirrors/` there are exactly three differences, and nothing else:
   - the registry prefix `localhost:5000/ocp4` is replaced with the example registry's (`quay.dc1.example.com/ocp4`, `harbor.edge.example.com:8443/mirror/ocp`)
   - mirror-set entries are sorted by `source` (`just sort`)
   - files are formatted by yamlfmt (`just fmt`)

   Each `cluster-resources/kustomization.yaml` is generated by `kustomize create --autodetect` and contains only `apiVersion`, `kind` and `resources`.
   Any customisation belongs in a component or a wrapper.
2. **Overlay component order is load-bearing.**
   It must be `ocp-version/<x.y>`, then `common`.
   Kustomize applies a kustomization's included components before its own patches, and patches run in order.
   The whole version-selection mechanism depends on this.
   Don't nest `common` inside a version component, and don't add anything to `common` that changes ClusterCatalog `availabilityMode`.
3. **Kind-only targets are only safe inside a catalog wrapper.**
   These are the `labels` field and the IDMS/ITMS patches in `components/catalogs/<catalog>`, and they rely on the wrapper holding one catalog's objects.
   In an overlay, which holds every catalog, use name-anchored targets instead, as `rename-catalogsources` does.
4. **Don't rename CatalogSources in a wrapper.**
   A wrapper holds every OpenShift version's CatalogSource, and renaming them there collides.
   Renaming happens in `common`, after the version component has deleted the other versions.
5. **The IDMS/ITMS rename must stay in the wrapper.**
   Every oc-mirror run names its mirror set `idms-operator-0`, so the names collide as soon as catalogs are merged.
6. **Target names are anchored Go (RE2) regexes**, with no lookahead.
   Write them as whole-name patterns, e.g. `cs-redhat-operator-index-v\d+-\d+`.
   Inside YAML flow maps (`{...}`), use `\d`, not `[0-9]`: an unquoted `[` breaks parsing.
7. **Stable names and label keys are a contract with clusters.**
   Don't change a CatalogSource name (`redhat-operators`, …) or the `catalogs.example.com/*` label keys and values unless asked to.
   That includes renaming a catalog directory in `mirrors/`, because its name is the CatalogSource name for new catalogs and the key for its components.

## Verifying a change

Required on `PATH` (the README's Development section says what each is for):

- [just](https://github.com/casey/just)
- [kustomize](https://github.com/kubernetes-sigs/kustomize) v5
- [yq](https://github.com/mikefarah/yq) v4 (mikefarah's)
- [yamlfmt](https://github.com/google/yamlfmt)
- `envsubst` (gettext)
- [lefthook](https://github.com/evilmartians/lefthook), for the hooks

```bash
just build    # clean target/, regen (sort mirror sets, regenerate files, yamlfmt), render overlays into target/
just check    # kustomize build every overlay and mirror dir
```

Run `just build` twice: the second run must change nothing.

For refactors, render before and after, and diff:

```bash
for d in overlays/*/*; do kustomize build "$d" > "/tmp/before-${d//\//_}.yaml"; done
# ...make the change...
for d in overlays/*/*; do kustomize build "$d" | diff -q "/tmp/before-${d//\//_}.yaml" - ; done
```

What correct overlay output looks like:
- one CatalogSource per catalog, with its stable name and that version's image
- only that version's ClusterCatalogs `Available`, and the rest `Unavailable`
- one IDMS per catalog, named after the catalog, entries sorted by `source`
- one ITMS for each catalog that has one (in this repo, `redhat-operators`), named the same
- `OperatorHub/cluster`
- no `catalogs.example.com/ocp-selected` label left anywhere

After a documentation change, check that every path mentioned in the READMEs exists.

## Conventions

- **Keep it simple, for human readers.**
  By default, scripts and READMEs should be as simple as the task allows, so a person can read them top to bottom and follow along.
  In scripts, that means straightforward bash: no clever one-liners, abstractions or options nobody asked for, and a short comment where intent isn't obvious.
  In docs, it means short sections and plain sentences.
  Only add complexity when the task really needs it.
- **YAML comments** say what a file does and anything order-sensitive.
  They don't mention tooling, "generated" or "hand-written".
  Each file starts with a short header comment, as the existing files do.
- **Docs.**
  - `README.md` is for platform engineers adopting the layout: concise, no implementation detail.
    Its `Development` section lists the just recipes, the pre-commit hook and why mirror sets are sorted; keep its recipe table in step with `justfile`.
  - `components/ocp-version/README.md` holds the version-selection mechanics.
  - `examples/README.md` describes the oc-mirror runs.
  - Keep all three consistent with the YAML when you change the structure.
  - Markdown style: one sentence per line, with no limit on line length.
    List items and blockquotes too: a list item's later sentences go on their own lines, indented to the item's text.
    Tables and code blocks are left as they are.
  - Markdown tables are formatted the way IntelliJ auto-formats them: each column padded to its widest cell, with one space either side of the cell text, and a separator row of dashes spanning each column's full width (no alignment colons).
    For example:

    ```
    | Recipe                | What it does                         |
    |-----------------------|--------------------------------------|
    | `just` / `just build` | Runs `clean`, `regen`, then `render` |
    ```
- **Adding a version, catalog or registry**: follow the how-tos in `README.md`.
  New versions and registries need no manual copying: `just build` generates their version components and overlays from `mirrors/`.
  New catalogs only need their `cluster-resources/`: `just build` creates their catalog and rename components; check `base-catalog` in the new catalog component.
  New registries need `components/registries/<registry>` by hand.
- **Regenerating `examples/`** needs oc-mirror, registry credentials and a throwaway local registry; see `examples/README.md`.
  Don't do it unless asked.
  It downloads images, and it changes every file's `createdAt`.
- **Don't commit, push or stage** unless the user asks.
